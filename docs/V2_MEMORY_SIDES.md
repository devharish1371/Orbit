# One memory, two sides — V2.6

Either member can add their own text, photo or voice to an already-kept photo. One optional
side per person; a voice makes a photo with a voice on its back. An explicit turn/open control
and ordinary buttons supply a keyboard/screen-reader alternative to motion. Playback is
always chosen; changing faces stops playback. Missing/removed contributions are a partial
memory, with no overdue or relationship-score prompt. The anniversary letter stays outside
Orbit.

The root post remains the single Keep/expiry/unsend/collection unit. Each member alone may
replace/remove their contribution. Removing Keep applies the normal root expiry to the whole
memory and removes phone copies after reconciliation; unsending the front hides all sides.
New contribution bytes are authoritative Storage sizes and count atomically toward Keep quota.
Files are deleted only through Storage API, including extras during retention. Replaced sides
become unreferenced uploads and follow ordinary orphan collection.

A bounded, server-produced manifest accompanies the root. Old clients can still show its
front; server quota/retention include all files. Updated phone copies include every side and
invalidate on revision changes; both-phone status cannot be inferred from the front alone.
Exports include each file once with side ownership/ordering. Cloud archiving must include the
whole manifest, compatible phones, independent backup and both members' explicit consent.

QA uses synthetic content and disposable accounts. No real partner contact, microphone use
or existing memory deletion. Native capture/playback/gesture/offline/two-phone checks remain
in the deferred task #7 batch; no APK handover is requested.
